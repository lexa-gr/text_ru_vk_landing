# Tilt + cursor-spotlight + parallax для карточек

## 1. Что делает эффект

Карточка наклоняется в сторону курсора (до 2,5° на ось), за курсором ходит мягкое световое пятно, а внутренние слои — фон, текст, кнопка — смещаются на разную глубину, так что содержимое выглядит лежащим *под* стеклянной оболочкой карточки. Эффект включается только на устройствах с мышью/трекпадом и не навешивается на touch и при `prefers-reduced-motion`.

**Где код в этом проекте.** Проект — React + TypeScript, файлов `style.css` / `script.js` нет; роль «скрипта» играют модули в `src/effects/`, роль «стилей» — общий [parallax.css](../src/styles/parallax.css) и CSS компонентов. Логика от фреймворка не зависит: это обычный DOM-код, React подключает его одним хуком.

**Один пульт управления:** все числа эффекта (глубина и вынос слоёв, угол наклона, перспектива, плавность) лежат в одном файле — [parallax.config.ts](../src/effects/parallax.config.ts). Блоки описывают только *какой слой чем является* (`data-parallax="back | mid | front"`), а не числа.

| Файл | Что внутри |
|---|---|
| `src/effects/parallax.config.ts` | **все настройки эффекта**: слои (глубина, вынос), угол, перспектива, плавность |
| `src/effects/pointer.ts` | нормализация курсора, проверка устройства (`matchMedia`) |
| `src/effects/tilt.ts` | наклон карточки, класс 3D-режима |
| `src/effects/spotlight.ts` | CSS-переменные светового пятна, класс наведения |
| `src/effects/parallax.ts` | движок слоёв (читает `data-parallax` и значения из конфига) |
| `src/effects/card-effects.ts` | склейка: события мыши → точные целевые значения transform, длительность CSS transition |
| `src/hooks/useCardEffects.ts` | React-обёртка (`useEffect` → `initCardEffects`) |
| `src/styles/parallax.css` | общий CSS: 3D-режим (preserve-3d/will-change/базовый transform) постоянный на десктопе с мышью, не только во время наклона — см. §6, грабли №4 |
| `src/components/{ActionCard,ToolCard,PriceCard,ActivationCard}/…`, `src/sections/Cta/…` | разметка слоёв и стили конкретных блоков (интеграция) |

## 2. Архитектура решения

### 2.1 Позиция курсора → диапазон −1…1

Расчёт опирается на `card.getBoundingClientRect()` и **четыре поля**: `left`, `top`, `width`, `height` (`right`/`bottom` не нужны) плюс `event.clientX/clientY`:

```
x = (clientX − (left + width / 2))  / (width  / 2)      → −1 слева … 0 центр … +1 справа
y = (clientY − (top  + height / 2)) / (height / 2)      → −1 сверху … 0 центр … +1 снизу
```

Значения зажимаются в `[−1, 1]` (`clamp`). `rect` **кэшируется** и перечитывается только на `mouseenter`/`resize` (не на каждый `mousemove` — см. §6, «Активные ограничения»: раньше рект перечитывался на каждом движении мыши, и это форсировало синхронный layout прямо в обработчике события). Нормализация по половине размера даёт одинаковую «силу» эффекта на карточках разных размеров и пропорций.

### 2.2 Один источник данных, три эффекта

Это **не три независимых обработчика**. У каждой карточки один набор слушателей (`mouseenter`, `mousemove`, `mouseleave`) и одно состояние; эффекты — его потребители:

```
mouseenter / mousemove / mouseleave      (навешены на КАЖДУЮ карточку отдельно)
        │
        ├─► rect = getBoundingClientRect()   (кэш, перемеряется на enter/resize)
        │
        ├─► x, y = нормализованная позиция курсора (−1…1)         ← точное целевое значение,
        │        │                                                  БЕЗ сглаживания в JS
        │        ├─► TILT      style.transform карточки — пишется ОДИН раз на событие
        │        │             perspective() rotateX() rotateY()
        │        └─► PARALLAX  style.transform каждого слоя [data-parallax] — тоже один раз
        │                      translate3d(x·shift, y·shift, depth) [scale]
        │                      (shift и depth берутся из parallax.config.ts по имени слоя)
        │
        │        Интерполяцию между старым и новым transform делает БРАУЗЕР через
        │        `transition: transform` (styles/parallax.css) — JS не считает промежуточные
        │        кадры и не использует requestAnimationFrame, см. §2.3.
        │
        └─► SPOTLIGHT   «сырая» позиция курсора → CSS-переменные --x, --y, --spot-r
                        + класс --hovered → CSS-transition прозрачности
```

Разделение сделано намеренно:

- **Tilt и parallax** — пишутся за один и тот же синхронный вызов (`track()` в card-effects.ts), поэтому наклон карточки и смещение слоёв всегда синхронны. Оба получают ОДИН и тот же `transition-duration`, выставленный туда же, синхронно — поэтому идут в одной фазе и при CSS-интерполяции.
- **Spotlight** берёт *несглаженную* позицию курсора: пятно должно липнуть к курсору без задержки, иначе оно «плывёт» отдельно от указателя. JS лишь кладёт числа в CSS-переменные, весь вид (градиент, blur, обрезка по скруглению, fade) — в CSS.

**Модель наклона.** Карточка «продавливается» там, где курсор: `rotateY = x · maxAngle`, `rotateX = −y · maxAngle` (минус — потому что в CSS положительный `rotateX` поднимает нижнюю кромку к зрителю). Перспектива задаётся прямо в `transform` карточки (`perspective(900px) …`), так что каждая карточка наклоняется вокруг *своего* центра, а родителю `perspective` не нужен.

**Модель глубины.** Три слоя в одной 3D-сцене (`transform-style: preserve-3d` на карточке — постоянно, не только во время наклона, см. §6 грабли №4) плюс фон. Слой задаётся одним атрибутом `data-parallax="…"`, числа — в `parallax.config.ts`. От зрителя вглубь:

| Слой | `data-parallax` | z | Глубина / вынос сейчас | Роль |
|---|---|---|---|---|
| Передний | `front` | +1 | `+40` / `+14` px | плашка скидки, иллюстрации, плитки — перед стеклом, едут вслед за курсором |
| Стекло/оболочка (блик + кромка) | — (только CSS) | 0 | не двигается | всегда поверх содержимого |
| Средний | `mid` | 0 | `0` / `0` | тело карточки: наклоняется только вместе с ней |
| Задний | `back` | −1 | `−14` / `−4` px | логотип, текст, стрелка — под стеклом, едут против курсора |
| Фон | `plate` | (глубже `back`) | `back.depth × 2` = `−28` / `0` | белая/цветная плита карточки, самый дальний слой |

*Глубина* (`depth`) — сдвиг слоя по оси Z, *вынос* (`shift`) — на сколько пикселей слой уезжает вбок при курсоре у края карточки (знак = направление). Слои с отрицательным Z смещаются **против** курсора (`shift < 0`) — как предметы за окном при взгляде сбоку. Фон (`plate`) автоматически получает компенсацию перспективы: она уменьшает слой глубже плоскости карточки в `P/(P−z)` раз, и, чтобы его контур совпадал с оболочкой, он масштабируется обратно на `(P−z)/P`.

**Почему глубина фона не задаётся отдельно.** Фон обязан лежать глубже `back`: иначе непрозрачная плита закроет содержимое. Чтобы это нельзя было сломать одной правкой, глубина фона выводится из `back.depth` (`plateDepthFactor`).

**Точечное исключение.** Атрибутом `data-parallax-depth="30"` можно переопределить глубину одного элемента (так сделана плитка Текст.ру в баннере: ближе к стеклу, чем плитка VK). Использовать редко: это отступление от общего конфига.

**Почему фон вынесен в отдельный слой.** Если бы фон был на самой карточке, он закрыл бы всё, что ушло за плоскость карточки (непрозрачный фон рисуется в плоскости z = 0). Поэтому у самой карточки фона нет, он живёт в `__base` слоем `plate`, а «оболочкой» служит прозрачный слой с бликом.

### 2.3 Плавность

**Комбинация**: движение — CSS `transition: transform`, «включатель» длительности — JS.

- JS на каждое событие курсора (`mouseenter`/`mousemove`) пишет ТОЧНОЕ целевое значение `style.transform` карточки и каждого слоя, без промежуточных кадров и без `requestAnimationFrame`. Интерполяцию от текущего отображаемого значения к новому целевому делает браузер через CSS `transition-property: transform` (см. `styles/parallax.css`).
- Перед записью нового значения JS выставляет `element.style.transitionDuration` — разную для двух фаз: короче, пока курсор внутри карточки (быстрый отклик на `mousemove`, значения — `PARALLAX.motion.followMs`), и длиннее при возврате в покой после `mouseleave` (`PARALLAX.motion.releaseMs`, мягкий возврат). Длительность и timing-function выставляются ОДНОВременно на карточку и все её слои — поэтому наклон и параллакс остаются в одной фазе, хотя каждый элемент анимируется своим независимым CSS transition.
- `mousemove` посреди уже идущего transition просто задаёт браузеру новую цель: он не «перезапускает» анимацию с нуля, а продолжает от текущего отображаемого значения к новой точке (сохраняя видимую непрерывность позиции; кривая ускорения при этом у каждого такого «перенацеливания» своя, но для мелких шагов между соседними `mousemove` это на глаз незаметно).
- Полный возврат в покой JS обнаруживает через событие `transitionend` на самой карточке (а не эпсилон-порогом, как раньше) — именно тогда снимается класс `TILTING_CLASS`. Если курсор вернулся раньше, чем анимация возврата доиграла, браузер сам шлёт `transitioncancel` вместо `transitionend` — лишний код для этого случая не нужен.
- В CSS вне этого — переходы, где траектория и так не зависит от курсора: `opacity` блика (появление 200 мс / затухание 300 мс) и hover кнопки (`transform` 220 мс).

**Почему теперь CSS `transition: transform`, а не JS-лёрп через requestAnimationFrame.** Первая версия ядра как раз использовала rAF с ручным экспоненциальным лёрпом (см. историю ниже, §6) — именно с ней и была вся история мигания текста. Сравнение со сторонним Atropos (`atropos.js`, atroposjs.com) — он анимирует ТОЧНО так же, как теперь и это ядро: пишет целевой `transform` один раз на событие курсора и отдаёт интерполяцию `transition: transform` — показало, что при живой мыши на реальном железе он не мигает, хотя внутри у него тот же переход «плоский transform в покое → matrix3d при наведении», который раньше считался главной причиной. Это указывает, что настоящая причина мигания была не в ПРЕДСТАВЛЕНИИ матрицы (§6, «грабли»), а в том, что JS писал `style.transform` на КАЖДОМ кадре rAF (~60+ раз в секунду, пока курсор двигался) — такая частая перезапись стиля с главного потока, судя по всему, и провоцировала редкий сбой рендера. Переход на событийную модель (записать один раз, отдать интерполяцию браузеру) убирает эту частую перезапись полностью, а заодно и упрощает код: не нужен ни `requestAnimationFrame`, ни ручной лёрп, ни эпсилон-порог «дошли до цели».

Старые (уже неактуальные) аргументы против CSS transition, оставлены для истории, чтобы не наступать на те же грабли при пересмотре решения ещё раз:

1. Опасение «CSS-transition при смене цели перезапускает кривую с нуля, отклик станет ступенчатым» — на практике для частых мелких шагов (`mousemove` на реальной скорости движения мыши) незаметно; в этом ядре и в Atropos работает гладко.
2. Опасение «слоям параллакса и карточке нужна одна фаза, а у CSS transition каждый элемент независим» — решается тем, что JS выставляет одинаковый `transition-duration`/`transition-timing-function` на карточку и слои синхронно, одним вызовом, до записи новых значений transform.
3. Опасение «постепенное нарастание глубины и зависимость от `dt` не выразить в CSS» — оказалось не нужно: раз JS сразу пишет полную целевую глубину, а не «долю» от неё, CSS transition сам плавно доводит Z (как и X/Y) от старого значения к новому за один проход.

## 3. Точки настройки

| Что менять | Где | Значение сейчас |
|---|---|---|
| Максимальный угол наклона (на ось, °) | `PARALLAX.maxAngle` в `parallax.config.ts` | `2.5` (диапазон 2–3) |
| Сила перспективы | `PARALLAX.perspective` (влияет и на компенсацию масштаба фона) | `900` px (800–1000) |
| **Глубина** слоя по Z (px) | `PARALLAX.layers.{back,mid,front}.depth` | `−14` / `0` / `+40` |
| **Вынос** слоя вбок (px, знак = направление) | `PARALLAX.layers.{back,mid,front}.shift` | `−4` / `0` / `+14` |
| Глубина фона (всегда глубже `back`) | `PARALLAX.plateDepthFactor` — множитель к `back.depth` | `2` (то есть `−28`) |
| Длительность CSS transition пока курсор внутри карточки | `PARALLAX.motion.followMs` | `150` мс (меньше — резче) |
| Длительность CSS transition возврата в покой | `PARALLAX.motion.releaseMs` | `320` мс |
| Диаметр пятна | `SPOT_RADIUS_RATIO` в `spotlight.ts` — радиус как доля **меньшей стороны** карточки; в CSS запасное `--spot-r` | `1` (радиус = меньшая сторона, диаметр = 2×) |
| Яркость пятна | стопы градиента `.…__glow` в CSS | `0.125` в центре, `0.06` на 45 % |
| Размытие пятна | `filter: blur()` у `.…__glow` | `20px` |
| Запас слоя пятна за границы карточки | `--glow-bleed` у `.…__spotlight` (должен быть ≥ ~1,5 × blur) | `30px` |
| Кромка стекла | `box-shadow: inset` у `.…__spotlight` | `1px`, `rgba(255,255,255,.18)` |
| Появление / затухание пятна | `transition` у `.…__spotlight` и `--hovered` | `200 мс` / `300 мс` |
| Какому слою принадлежит элемент | атрибут **в разметке** `data-parallax="plate \| back \| mid \| front"` | фон — `plate`, текст и стрелка — `back`, тело — `mid`, плашки и иллюстрации — `front` |
| Точечное переопределение глубины одного элемента | `data-parallax-depth="30"` (необязательно, использовать редко) | только плитка Текст.ру в баннере: `30` вместо `40` |
| Hover кнопки-стрелки | `@media`-блок в конце CSS | `scale(1.1)`, стрелка `+ rotate(45deg)`, 220 мс |
| Порог включения эффекта | `FINE_POINTER_QUERY`, `REDUCED_MOTION_QUERY` в `pointer.ts` | см. ниже |

**Что проверяется на touch/мобильных.** В этом проекте хук `useCardEffects` подключает эффект только на десктопной раскладке (`≥ 1200px`, `DESKTOP_QUERY` в `useMediaQuery.ts`) и снимает при сужении окна — само ядро об этом не знает. Сам эффект (слушатели вообще) включается только если одновременно:

- `(hover: hover) and (pointer: fine)` — основной ввод умеет наводиться и точный (мышь, трекпад); на телефонах/планшетах это `false`;
- **нет** `(prefers-reduced-motion: reduce)`.

Оба условия подписаны на `change`: подключили мышь к планшету — эффект включится сам, включили «уменьшение движения» — выключится. Те же условия продублированы в CSS (`@media`) для hover кнопки, чтобы на touch не «залипал» `:hover`.

## 4. Ядро vs интеграция

### Ядро — переносится как есть

- **Настройки:** `parallax.config.ts` — единственное место с числами эффекта; при переносе меняйте только его.
- **Расчёт координат:** `pointer.ts` → `getNormalizedPointer`, `isCardEffectsSupported`.
- **Tilt:** `tilt.ts` (`applyTilt`, `beginTilt`, `resetTilt`).
- **Spotlight (JS-часть):** `spotlight.ts` (переменные `--x/--y/--spot-r`, класс наведения).
- **Параллакс-движок:** `parallax.ts` — сам ничего не знает о разметке, читает слои по `[data-parallax]`, числа берёт из конфига.
- **Склейка:** `card-effects.ts` → `initCardEffects(cards)`.
- **Ядро в CSS:** `styles/parallax.css` (3D-режим постоянный на десктопе с мышью — preserve-3d/will-change/базовый transform не ждут `mouseenter`, см. §6 грабли №4), слой стекла со скруглением/`overflow: hidden`/`opacity`, слой пятна с `radial-gradient` на `--x/--y/--spot-r`.

Единственная «утечка» проекта в ядро — два имени классов, зашитые в константы: `TILTING_CLASS = 'action-card--tilting'` (`tilt.ts`) и `HOVERED_CLASS = 'action-card--hovered'` (`spotlight.ts`). При переносе переименуйте их под свой префикс (см. §5).

### Интеграция под этот лендинг — не переносить, а переписать

- **Селекторы и подключение:** `useCardEffects(cardsRef, '.action-card')` в `Hero.tsx` — эффект вешается на обе карточки блока `.hero__cards`, каждая живёт независимо.
- **Разметка слоёв:** в `ActionCard.tsx` — какой элемент является фоном (`plate`), содержимым и стрелкой (`back`), стеклом.
- **Значения параллакса** (глубина и вынос слоёв) подобраны под размер этих карточек (236 px высотой) и лежат в `parallax.config.ts`; логотип, текст и стрелка — *один* слой `back`.
- **Цвета фона** (`--premium`/`--pro`), логотипы, бейдж, типографика.
- **Кнопка-стрелка** из двух SVG (рамка + стрелка) и её hover — специфика макета.
- **Обвязка React:** `useCardEffects.ts`.

### Второе применение: карточки блока `.tools`

`Tools.tsx` вешает то же ядро на четыре карточки: `useCardEffects(gridRef, '.tool-card')`. Отличия только в интеграции:

- **Слои** (`ToolCard.tsx`): фон + рамка (`__base`, `plate`) → логотип, заголовок и текст одним слоем (`__content`, `back`) → стекло (`__spotlight`) → иллюстрация (`__image`, `front`). Рамка и `box-shadow` остаются на самой карточке-оболочке (первая — на слое фона, чтобы контур совпадал с ним).
- **Иллюстрация перед стеклом.** Ракета («Запускайте рекламу…») и документ («Доводите текст…») — часть своих карточек с положительной глубиной и смещением *вслед* за курсором; текст и логотип уходят вглубь. Разница глубин между ними (`front` против `back`) и даёт усиленный параллакс. В DOM иллюстрация стоит после стекла — так порядок совпадает с глубиной и в плоском состоянии.
- **Поворот и обрезка иллюстрации — во вложенной рамке** (`__frame`): JS перезаписывает `transform` слоя параллакса, поэтому `rotate(33.13deg)` и `overflow: hidden` нельзя держать на самом слое.
- **Имена классов в ядре** (`action-card--tilting` / `--hovered`) остались общими, состояния описаны как `.tool-card.action-card--tilting` и `.tool-card.action-card--hovered`.
- **Пятно света тонируется** (`--tool-glow-rgb`: красный у карточек Текст.ру, синий у VK Рекламы): белый блик на белой карточке не виден.
- **Ракета заходит на соседнюю карточку.** Карточке (`.tool-card--launch-ads`) задан `z-index: 1` постоянно — не только на время наклона, см. §6 грабли №7 (раз `will-change` у карточки теперь тоже постоянный, она и в покое уже свой контекст наложения).

### Третье применение: карточки тарифов `.pricing__cards`

`Pricing.tsx`: `useCardEffects(cardsRef, '.price-card')` — обе карточки (ПРО-аккаунт и Премиум-подписка). Слои (`PriceCard.tsx`), от дальнего к ближнему:

| Слой | `data-parallax` | Что |
|---|---|---|
| `__base` | `plate` | белый фон карточки + цветной фон шапки |
| `__heading`, `__price` | `back` | логотип, заголовок, подзаголовок; цена — оба под оболочкой |
| `__body` | `mid` | преимущества и кнопка: наклоняются только вместе с карточкой |
| `__spotlight` | — | стекло |
| `__discount` | `front` | плашка скидки — перед оболочкой |

Особенности интеграции:

- **Слои не прямые дети карточки.** Текст, цена и плашка лежат внутри `__head`/`__pricing`. Блок без `preserve-3d` «сплющивает» потомков в свою плоскость, поэтому эти два блока помечены `data-parallax-group`: общий CSS (`styles/parallax.css`) включает им `transform-style: preserve-3d` постоянно, так же как и самой карточке (сами они не двигаются).
- **Цветной фон шапки — часть слоя `__base`,** а не отдельный слой: у двух слоёв разные центры, и перспектива разводила бы их контуры (шапка «вылезала» бы за карточку). Высота шапки зависит от содержимого (у карточек 285 и 288 px), поэтому `__base` — `subgrid` по строкам сетки карточки, и его цветная часть всегда ровно по шапке.
- **`overflow: hidden` со скруглением** перенесён с карточки на `__base` (иначе плоская карточка «сплющила» бы 3D).
- **Белый блик на белом теле карточки не виден,** заметен только на цветной шапке; пятно не тонировалось (у тела нет собственного слоя стекла).

### Четвёртое и пятое применение: карточки подключения и баннер CTA

Тот же набор слоёв без исключений: `ActivationCard.tsx` (`plate` → шапка с логотипом `back` → тело `mid` → стекло) и `Cta.tsx` (`plate` со свечением → содержимое `back` → стекло → плитки `front`; плитка Текст.ру с точечной глубиной `data-parallax-depth="30"`). Подключение — `useCardEffects` с селекторами `.activation-card` и `.cta__banner`.

### Как подключить эффект новому блоку (в этом проекте)

1. На корень карточки — `data-parallax-card`; в компоненте — `useCardEffects(ref, '.моя-карточка')`.
2. Каждому значимому блоку внутри — `data-parallax="plate | back | mid | front"` в порядке DOM: фон → содержимое → стекло → передние слои. Обёртки между карточкой и слоем — `data-parallax-group`.
3. В CSS блока — только его внешний вид; 3D-режим и слои уже в `styles/parallax.css`. Силу эффекта меняйте в `parallax.config.ts`, а не в блоке.

**Чек-лист при переносе**

1. Карточка — `position: relative` и атрибут `data-parallax-card`, скругление задано на ней (`border-radius`); слои `base` и `glass` наследуют его (`inherit`).
2. Фон карточки — **на отдельном слое** (`data-parallax="plate"`), не на самой карточке.
3. Стекло — последним среди слоёв под ним, `pointer-events: none`, без `data-parallax`.
4. **Все значимые блоки внутри карточки — слои** (`plate`, `back`, `mid` или `front`), а порядок в DOM: фон → содержимое → стекло → передние слои. Причина: `will-change: transform` создаёт контекст наложения, и такой слой рисуется выше обычных соседей; непомеченное тело карточки оказалось бы под фоном. Блок «на нулевом уровне» помечайте `data-parallax="mid"`.
5. Между карточкой и слоем есть обёртка — пометьте её `data-parallax-group`.
6. На карточке, на слоях с `data-parallax` и на их предках до карточки **нет** `opacity < 1`, `filter`, `overflow ≠ visible`, `isolation`, `mix-blend-mode`, `clip-path`, `mask`, `backdrop-filter` (см. §6 — они «сплющивают» 3D).
7. Свои `transform` на карточке и слоях — переносить на обёртки (JS перезаписывает inline `transform`).
8. Проверьте, нет ли у карточки уже существующего CSS-правила вида `.section .card { transform: none }` (или похожего сброса) с специфичностью выше одного атрибут-селектора — оно молча забьёт базовый transform ядра и вернёт флику. Если есть — либо уберите его для этого элемента, либо (как в этом проекте) поднимите специфичность самого базового правила в ядре, а не в интеграции, см. §6 п.8.
9. Не переносите старую версию ядра с `requestAnimationFrame` и ручным лёрпом — текущая версия анимирует через CSS `transition: transform` (см. §2.3); это и есть исправление мигания, найденное сравнением со сторонним Atropos.

## 6. Известные ограничения

**Проверялось / не проверялось.** Автоматически, в Chromium (Edge, headless) с эмуляцией мыши: значения `transform` на слоях и на карточке (в т.ч. представление матрицы в покое/на наведении — совпадает, скачков `matrix()`↔`matrix3d()` нет), направление смещений, возврат в покой через `transitionend`, независимость карточек, отсутствие ошибок консоли, отключение на touch (`hover: none`, `pointer: coarse`) и при `prefers-reduced-motion`; отсутствие изменений вёрстки в покое и отсутствие остаточных скачков в окне возврата (0–1100 мс после ухода курсора) — попиксельным сравнением последовательных скриншотов; пример из §5 отработал на голой странице поверх реальных файлов проекта. **Дополнительно подтверждено на живой мыши и реальном железе** (после перехода на CSS-transition модель, см. §2.3): текст не мигает и не исчезает при наведении/уходе курсора — это была цель всей переделки, и результат подтверждён автором проекта, а не только автоматическими проверками. **Не проверялось:** Safari, Firefox, реальные тач-устройства, GPU-рендер отдельно от визуального результата. Пункты про Safari ниже — риски по известным особенностям браузера, а не наблюдения.

**Грабли, на которые уже наступили**

1. **Положительный Z = «приподнятое» содержимое.** Первая версия выдвигала логотип/текст к зрителю и двигала их *вслед* за курсором — выглядело как наклейка над поверхностью. Правильно для «под стеклом»: отрицательный Z и смещение *против* курсора.
2. **Непрозрачный фон на самой карточке скрывает всё, что «ниже» неё.** Поэтому фон вынесен в слой `__base`, см. §2.2.
3. **Разные слои для логотипа и текста читаются как «летящий отдельно логотип».** Если логотип двигается заметно быстрее соседнего текста, кажется, что он на другом этаже. Логотип и текст — один слой; отдельным слоем оставлена только интерактивная кнопка.
4. **Постоянный `preserve-3d` портит сглаживание текста — ЕСЛИ карточка в покое стоит с identity-transform.** Первая версия держала `preserve-3d` постоянно, но с `transform: none`/`translate3d(0,0,0)` в покое: карточка и её слои уходили в композитные слои, и в покое менялась растеризация — на первом экране отличалось ~18 тыс. пикселей на краях глифов и иллюстрации. Тогдашнее лечение — включать `preserve-3d` классом только от `mouseenter` до полного возврата (`TILTING_CLASS`) — снимало этот симптом, но открывало другой: **слои всё равно приходится держать композитными и в покое** (`will-change: transform`, только на десктопе с мышью), иначе в конце возврата слои разом схлопываются в плоскую отрисовку, и текст на кадр меняет сглаживание — «мигание» через ≈ 0,75 с после ухода курсора (замер: при 100% масштабе 4,3% пикселей карточки за один кадр; после правки will-change — 0,09%).
   **Текущее решение** (см. §2.2 и `styles/parallax.css`) убирает оба симптома разом: `preserve-3d` теперь ПОСТОЯННЫЙ (не завязан на `TILTING_CLASS`), но и состояние покоя карточки/слоёв больше не identity — у него тот же набор функций transform, что и у активного (perspective+rotateX/Y у карточки, translate3d у слоёв), просто с почти нулевыми числами. Раз карточка ВСЕГДА в 3D-режиме — переключения растеризации нет вообще, ни на входе курсора, ни на выходе, ни при использовании preserve-3d. Цена та же, что и раньше: текст в карточках рисуется с серым, а не субпиксельным (ClearType) сглаживанием — но теперь стабильно, без кадра-скачка в любую сторону.
5. **`will-change: transform` создаёт контекст наложения.** Слой рисуется выше обычных соседей, поэтому непомеченный блок карточки (например, «нулевое» тело) оказывается ПОД слоем фона и исчезает. Отсюда правило: все блоки карточки — слои (`plate`/`back`/`mid`/`front`), порядок в DOM — фон → содержимое → стекло → передние слои.
6. **Тонкая линия стрелки после разделения SVG сглаживается иначе** (~530 px на первом экране, максимум различия небольшой). Положение не менялось — это чисто субпиксельное сглаживание.
7. **`z-index` на карточке при выходе иллюстрации за её границы.** Если карточку сделать `z-index: 1` навсегда, её тень ляжет поверх соседней карточки (у карточек `.tools` — полоса ≈ 30 px на верхнем крае нижней); если не поднимать вовсе — соседняя перекроет выступающий кусок иллюстрации. Раньше `z-index` ставился у карточки только на время наклона, а в покое — у самой иллюстрации; но раз `will-change: transform` теперь постоянный (см. п.4), каждая `[data-parallax-card]` и без того уже свой изолированный контекст наложения постоянно — z-index потомка не может «вырваться» из него в покое так же, как не мог во время наклона. Поэтому `z-index: 1` у `.tool-card--launch-ads` теперь тоже постоянный (не привязан к `TILTING_CLASS`).
8. **Специфичность базового transform’а может проиграть чужому правилу.** Базовый transform карточки в покое (п.4) задан селектором `[data-parallax-card]` — специфичность как у одного класса. Если у какой-то секции уже ЕСТЬ свой CSS-сброс вида `.some-section .some-card { transform: none }` (два класса — специфичность выше), он молча перебивает базовый transform, карточка в покое возвращается к identity, и вся защита от п.4 перестаёт работать именно для неё (при этом JS продолжает исправно наклонять её при наведении inline-стилем — баг незаметен по функциональности, только по мельканию). Ровно так на Hero перебивало правило `.hero__cards .action-card { transform: none }` (часть архитектуры интро-заставки, не связанная с параллаксом). Лечится в самом ядре, без правок конкретных секций: селектор базового transform’а у карточки намеренно завышен по специфичности — `[data-parallax-card]` повторён трижды подряд (0,3,0 вместо 0,1,0). `!important` для этого не годится: он перебил бы и inline-transform, который пишет JS во время наклона, и эффект перестал бы двигаться вообще. При переносе ядра на новый проект стоит поискать похожие «сбросы» transform у карточек — они могут быть где угодно.

**Активные ограничения**

- **`preserve-3d` «сплющивается» группирующими свойствами.** `opacity < 1`, `filter`, `overflow` не `visible`, `isolation: isolate`, `mix-blend-mode`, `clip-path`, `mask`, `backdrop-filter`, `contain: paint` на карточке или на промежуточном предке слоя обнуляют глубину: слои продолжат смещаться по X/Y, но Z и перспектива пропадут. Поэтому `overflow: hidden` есть только у листовых слоёв (стекло), а не у карточки.
- **Конфликт с другими `transform`.** JS пишет inline `transform` на карточку и на каждый слой с `data-parallax` и перезаписывает CSS-`transform` (hover-подъём, анимации `@keyframes`, `translateY`). Такие трансформации нужно выносить на обёртку или на вложенный элемент — как сделано у кнопки-стрелки: слой параллакса — контейнер, а `scale/rotate` — на вложенных `<img>`.
- **Перспективная «усадка» содержимого.** При наведении слой на z = −14 при `perspective: 900px` выглядит на ≈ 1,5 % меньше и смещается к центру карточки (сильнее у элементов, далёких от центра). Это часть эффекта глубины; уменьшается снижением |depth| или ростом `perspective`.
- **Неточное совпадение фона и стекла.** Фон компенсируется масштабом только про центр карточки; при наклоне остаётся расхождение контуров ≈ 1 px (заметнее при светлой кромке стекла). Убирается уменьшением |depth| фона.
- **`getBoundingClientRect()` у уже наклонённой карточки** возвращает описанный прямоугольник трансформированного элемента — он отличается от «плоского» на доли пикселя при 2,5°. На практике обратной связи нет, но при больших углах (> 8–10°) нормализацию лучше считать от размеров без трансформации (`offsetWidth/Height`).
- **Пятно не сглаживается намеренно** и идёт чуть впереди наклона (у которого теперь CSS transition ≈ `PARALLAX.motion.followMs` = 150 мс). Это ощущается как «блик обгоняет поверхность»; если мешает, добавьте `--x/--y` в тот же список transition-свойств в CSS.
- **Только `mouse*`-события, не `pointer*`.** Для мыши/трекпада этого достаточно; перо со «зависанием» и гибридные устройства не тестировались.
- **`getBoundingClientRect()`** кэшируется и перемеряется только на `mouseenter`/`resize`, не на каждый `mousemove` (было исправлено отдельно: реальный Performance-трейс показывал непрерывный форсированный layout на каждое движение мыши). Для десятков карточек одновременно на экране имеет смысл ещё и `IntersectionObserver`, чтобы подключать слушатели только видимым.
- **Сглаживание текста.** Текст в слоях карточек рисуется в градациях серого, а не субпиксельно (ClearType): во время эффекта — из-за композитного слоя, в покое — потому что слои держатся композитными заранее (см. «Грабли», п. 4). Заметно только на самых тонких начертаниях.
- **На экранах с высокой плотностью пикселей (масштаб 200%) остаётся кадр «перерастеризации» при выходе из 3D.** Замер: около 8% пикселей карточки за один кадр в конце возврата (при 100% — ≈ 0,1%). Причина — 3D-матрица самой карточки (`perspective()` + `preserve-3d`): в таком контексте текст растеризуется мягче, чем плоский. `will-change`, `backface-visibility`, `text-rendering` на это не влияют; уходит только при отказе от `preserve-3d` или transform у карточки (тогда теряется глубина параллакса). Не устранено.
- **Риски Safari (не проверялось):** известны артефакты `overflow: hidden` + `border-radius` у наклонённых потомков (обрезка по скруглению может «мигать»; обычное лечение — `-webkit-mask-image: -webkit-radial-gradient(white, black)` на слое-маске) и особенности `preserve-3d`/`will-change`. При переносе сначала проверьте Safari.
