# Blur-morph: смена слова в заголовке

## 1. Что делает эффект

Одно слово в заголовке по кругу заменяется следующим из списка: текущее растворяется в размытие (`blur` + fade), пока оно невидимо — в DOM подставляется следующее, после короткой паузы оно «собирается» из расфокуса. Ширина контейнера слова всегда равна самому длинному слову списка, поэтому остальной текст и кнопки под заголовком не двигаются. При `prefers-reduced-motion: reduce` показывается первое слово без смены.

**Где код в этом проекте.** Проект — React + TypeScript; логика — обычный DOM-код без зависимостей, React подключает его компонентом-обёрткой. (Файлов `style.css` / `script.js` в проекте нет.)

| Файл | Что внутри |
|---|---|
| `src/effects/word-morph.ts` | весь эффект: цикл, подмена текста, переключение класса, вкладка, reduced motion |
| `src/components/WordMorph/WordMorph.css` | визуал: сетка «призраков» для ширины, blur/opacity-переход |
| `src/components/WordMorph/WordMorph.tsx` | React-обёртка: разметка + `useEffect` → `initWordMorph` (интеграция) |
| `src/sections/Hero/Hero.tsx`, `Hero.css` | данные (массив слов), разметка заголовка, `nowrap` и `z-index` (интеграция) |

## 2. Архитектура решения

### 2.1 Модель: цикл из четырёх шагов, JS только переключает класс

Эффект — небольшой конечный автомат. JS решает **когда**, CSS решает **как выглядит**:

```
┌─ слово чёткое ── holdMs ─┐
│                          ▼
│   ① DISSOLVE   + класс --morphing        blur 0→10px, opacity 1→0   outMs, ease-in
│   ② SWAP       через outMs               слово невидимо → textNode.data = следующее
│   ③ GAP        пауза gapMs               слова не сливаются в один рывок
│   ④ ASSEMBLE   − класс --morphing        blur 10→0px, opacity 0→1   inMs, ease-out
│                          │
└──── inMs + holdMs ◄──────┘   (дальше снова ①; после последнего слова — первое)
```

Замер по кадрам (Edge, эмуляция; допуск ≈ ±16 мс — квантование `requestAnimationFrame`):

| Этап | Номинал | Измерено |
|---|---|---|
| Растворение до `opacity ≤ 0.02` | 350 | 349–351 |
| От начала растворения до подмены текста | 350 | 350–367 |
| Пауза перед сборкой | 120 | 116–134 |
| Сборка до `opacity ≥ 0.995` | 350 | 332–334 |
| Слово чёткое | 2200 | 2200–2233 |
| Период цикла | 3020 | 3017–3049 |

В момент подмены текста `opacity = 0` и `blur = 10px` во всех проверенных циклах — то есть замена слова не видна.

Всё состояние эффекта в DOM — это **один класс** (`--morphing`) и **один текстовый узел**. Нет ни JS-анимации свойств, ни `transitionend`-обработчиков: тайминги JS и длительности CSS зафиксированы в одном месте (`WORD_MORPH`) и передаются в CSS переменными `--morph-out`, `--morph-in`, `--morph-blur`, поэтому разъехаться не могут.

**Разные кривые для ухода и прихода — без JS.** У растворённого состояния (`--morphing`) свои `transition-duration` и `ease-in`, у чёткого — свои и `ease-out`. CSS берёт параметры перехода из *состояния-назначения*: добавили класс → работают параметры растворения; сняли → параметры сборки.

### 2.2 Стабильная ширина: «призраки» слов в одной ячейке грида

Контейнер слова — `display: inline-grid`, все слова кладутся в **одну ячейку** (`grid-area: 1 / 1`). Видимое слово одно, остальные — невидимые копии (`visibility: hidden`, `aria-hidden`), которые не рисуются, но занимают место. Ширина ячейки = ширина самой широкой копии.

Почему так, а не `min-width` в пикселях:
- `min-width: 590px` придётся подбирать под конкретный шрифт и размер и пересчитывать при любой правке (шрифт, размер, `letter-spacing`, список слов);
- «призраки» наследуют тот же шрифт, размер и `letter-spacing`, поэтому ширина всегда точна, а длиннейшее слово определяется браузером, а не «по количеству букв»;
- никакого JS-измерения и `ResizeObserver`.

Строка при этом не может перенестись (`white-space: nowrap` у заголовка), а высота остаётся высотой одной строки.

### 2.3 Таймеры: цепочка `setTimeout` с единственным идентификатором

Шаги планируются рекурсивной цепочкой: следующий `setTimeout` ставится только после срабатывания предыдущего, а функция `later()` перед каждым запуском вызывает `clearTimeout`. В любой момент активен **не более одного** таймера (проверено: максимум 1, `setInterval` не создаётся) — остановка и очистка сводятся к одному `clearTimeout`.

Почему не другие способы:
- **`setInterval`** — шаги разной длины пришлось бы разводить внутри одного тика; при возврате из фоновой вкладки очередь тиков может отработать пачкой.
- **`@keyframes` + `animationiteration`** — рабочая альтернатива (цикл в анимации, текст подменяется на границе итерации, когда слово невидимо). В этом проекте *не реализовывалась и не проверялась*: выбрана цепочка таймеров ради явных, независимо настраиваемых шагов (пауза, hold) и простого перезапуска при возврате на вкладку.

### 2.4 Жизненный цикл: вкладка, доступность, очистка

Единая функция `sync()` решает, что делать сейчас; вызывается при старте и по событиям `visibilitychange` и `change` у `prefers-reduced-motion`:

- **reduced motion** → показать первое слово, остановить таймеры (в CSS дополнительно `transition: none`);
- **вкладка скрыта** → остановить таймеры (браузер их замедляет, а переходы в фоне могут не отрисоваться);
- **вкладка видна** → снять класс и начать цикл заново с чёткого слова. «Зависнуть на середине перехода» нельзя: после возврата слово плавно проявляется из любого промежуточного состояния и через `holdMs` цикл продолжается.

Функция очистки, которую возвращает `initWordMorph`, снимает таймер и оба слушателя, возвращает первое слово и убирает CSS-переменные (нужно для SPA и React StrictMode, где эффект монтируется дважды).

Текст меняется **на месте** в существующем текстовом узле (`textNode.data`), структуру элемента эффект не трогает — поэтому фреймворк, отрисовавший этот узел, не ломается.

## 3. Точки настройки

| Что менять | Где | Значение сейчас |
|---|---|---|
| Список слов и их порядок | массив `HERO_WORDS` в `Hero.tsx` (в чистом HTML — массив в вашем `main.js`) | заявок, продаж, клиентов, результата |
| Сколько слово стоит чётким | `WORD_MORPH.holdMs` в `word-morph.ts` | `2200` мс (2000–2500) |
| Скорость растворения | `WORD_MORPH.outMs` | `350` мс (300–400) |
| Пауза между словами | `WORD_MORPH.gapMs` | `120` мс (100–150) |
| Скорость «сборки» | `WORD_MORPH.inMs` | `350` мс (300–400) |
| Сила размытия | `WORD_MORPH.blurPx` | `10` px (8–12) |
| Кривые перехода | `transition` в `.word-morph__word` (приход) и `transition-timing-function` в `--morphing` (уход) в `WordMorph.css` | `ease-out` / `ease-in` |
| Имя класса «растворено» | константа `MORPHING_CLASS` в `word-morph.ts` **и** селектор в `WordMorph.css` — менять парой | `word-morph__word--morphing` |
| Условие отключения анимации | `REDUCED_MOTION_QUERY` в `word-morph.ts` (+ `@media` в `WordMorph.css`) | `(prefers-reduced-motion: reduce)` |
| Запрет переноса строки | `white-space: nowrap` у заголовка (`Hero.css`) | включён |

Значения `WORD_MORPH` записываются в CSS-переменные элемента слова; значения после запятой в `var(--morph-…, 350ms)` — запасные на случай, если JS не отработал.

**Поведение при коротком списке.** Если слов меньше двух, `initWordMorph` ничего не делает (нечего менять).

## 4. Ядро vs интеграция

### Ядро — переносится как есть

- **`word-morph.ts` целиком**: `initWordMorph(element, words)`, `WORD_MORPH`. Не импортирует ничего, не знает о фреймворке и о разметке, кроме требования: `element` — элемент со **словом** внутри (его первый дочерний узел — текст).
- **CSS ядра** (`WordMorph.css`): контейнер `inline-grid`, общая ячейка, скрытые «призраки», blur/opacity-переход и состояние `--morphing`.

### Интеграция под этот лендинг — не переносить, а переписать

- **Слова и содержимое заголовка** — `HERO_WORDS`, статичная часть «От контента до » (`Hero.tsx`).
- **React-обёртка** `WordMorph.tsx`: генерирует «призраки» из массива слов и вызывает `initWordMorph` в `useEffect`. В другом фреймворке — своя обёртка на 10 строк или ручная разметка (см. §5).
- **Место в вёрстке**: `.hero__title { white-space: nowrap }` и `z-index` у `.hero__intro`, потому что строка «до результата» (730 px) шире блока заголовка по макету (690 px) и заходит на иллюстрацию.
- **Типографика**: размер, шрифт и `letter-spacing` заголовка — из глобальных стилей проекта; эффект их лишь наследует.

## 5. Минимальный пример переноса

Всё, что нужно на голой странице. Проверено: блоки `html`, `css` и `js` из этого раздела извлекались прямо из этого файла и запускались на отдельной странице вне проекта (`word-morph.ts` при этом просто транспилирован в JS, без правок).

**Шаг 0.** Скопируйте `src/effects/word-morph.ts`. Если проект без TypeScript — прогоните его через `tsc`, esbuild или Vite (в файле только аннотации типов); в нативных ES-модулях путь импорта — с расширением `./effects/word-morph.js`.

**index.html** — заголовок с динамическим словом. В разметке только видимое слово (это и есть no-JS fallback); «призраки» для ширины добавляет `main.js` из того же массива, чтобы список слов существовал в одном месте:

```html
<link rel="stylesheet" href="./word-morph.css" />

<h1 class="headline">
  От контента до
  <span class="word-morph"><span class="word-morph__word">заявок</span></span>
</h1>

<p class="after">Этот текст не должен сдвигаться при смене слов.</p>

<script type="module" src="./main.js"></script>
```

**word-morph.css** — ядро + минимальный внешний вид:

```css
.headline {
  margin: 40px;
  font: 700 64px / 1.2 system-ui, sans-serif;
  white-space: nowrap; /* слово не должно переноситься на другую строку */
}

/* Ядро: все слова в одной ячейке → ширина = самое длинное слово */
.word-morph { display: inline-grid; justify-items: start; }
.word-morph__sizer,
.word-morph__word { grid-area: 1 / 1; }

/* «Призраки»: невидимы, но задают ширину */
.word-morph__sizer { visibility: hidden; pointer-events: none; user-select: none; }

/* Ядро: чёткое состояние и «сборка» слова из расфокуса. --morph-* выставляет JS */
.word-morph__word {
  filter: blur(0px);
  opacity: 1;
  transition:
    filter var(--morph-in, 350ms) ease-out,
    opacity var(--morph-in, 350ms) ease-out;
}

/* Ядро: растворённое состояние (класс ставит JS) — уход с ease-in */
.word-morph__word--morphing {
  filter: blur(var(--morph-blur, 10px));
  opacity: 0;
  transition-duration: var(--morph-out, 350ms);
  transition-timing-function: ease-in;
}

@media (prefers-reduced-motion: reduce) {
  .word-morph__word { transition: none; }
}
```

**main.js** — список слов и подключение:

```js
import { initWordMorph } from './effects/word-morph.js'

// ✏ Слова по кругу; первое должно совпадать с текстом в разметке
const WORDS = ['заявок', 'продаж', 'клиентов', 'результата']

const word = document.querySelector('.word-morph__word')

// «Призраки» всех слов задают ширину контейнера (строятся из того же массива)
for (const text of WORDS) {
  const ghost = document.createElement('span')
  ghost.className = 'word-morph__sizer'
  ghost.setAttribute('aria-hidden', 'true')
  ghost.textContent = text
  word.before(ghost)
}

const dispose = initWordMorph(word, WORDS)
// dispose() — остановить эффект и вернуть первое слово (для SPA-размонтирования)
```

**Чек-лист при переносе**

1. `WORDS[0]` совпадает с текстом в разметке (первое слово — то, что видно до старта и при reduced motion).
2. Внутри `.word-morph__word` **только текстовый узел** — без вложенных тегов.
3. «Призраки» и видимое слово имеют **один и тот же** шрифт, размер и `letter-spacing` (наследуются от заголовка, не задавайте их только видимому слову).
4. Заголовок с `white-space: nowrap`, а самая длинная строка помещается в доступную ширину (см. §6).
5. Класс `--morphing` в CSS и константа `MORPHING_CLASS` в JS совпадают.

## 6. Известные ограничения

**Проверялось / не проверялось.** Проверено в Chromium (Edge, headless): хронология по кадрам (таблица в §2.1), порядок слов и возврат к первому, постоянство `top` кнопки, высоты заголовка и ширины контейнера слова, не более одного активного таймера и отсутствие `setInterval`, поведение при скрытии/возврате вкладки, `prefers-reduced-motion` (включая переключение флага «на лету»), отсутствие ошибок консоли; пример из §5 отработал на голой странице. **Не проверялось:** Safari, Firefox, реальные тач-устройства, GPU-рендер; скрытие вкладки эмулировалось событием `visibilitychange`, а не настоящим фоновым режимом браузера (реальное замедление таймеров не воспроизводилось).

**Грабли, на которые уже наступили**

1. **Слово длиннее отведённого места закрывается соседним элементом.** Строка «до результата» получилась 730 px при блоке в 690 px и заходила под иллюстрацию — пропадала последняя буква «а». Решение в проекте: `z-index` у блока заголовка поверх иллюстрации. Альтернативы: сдвинуть соседний элемент или взять слово покороче. Ширину контейнера при этом эффект определяет верно — проблема была именно в окружающей вёрстке.
2. **Кнопка под заголовком не должна зависеть от слова.** Если бы ширина брала текущее слово, следующий за строкой контент дёргался бы при смене; «призраки» в одной ячейке решают это без магических пикселей.
3. **Один и тот же селектор класса в JS и CSS.** Имя класса «растворено» дублируется в `word-morph.ts` и `WordMorph.css`; при переименовании легко поменять только одно место — слово перестанет растворяться (текст будет меняться рывком).

**Активные ограничения**

- **Слова только однострочные.** Многострочные слова и слова с `<br>` не поддерживаются: заголовок `nowrap`, слово — один текстовый узел.
- **Слово — обычный текст.** Вложенная разметка (`<em>`, иконки) внутри слова не поддерживается: эффект подменяет `data` текстового узла.
- **Дрейф таймеров.** Каждый шаг ставится после срабатывания предыдущего, поэтому задержки накапливаются: период цикла 3017–3049 мс при номинале 3020 мс. Для заголовка это неощутимо; синхронизировать несколько независимых экземпляров по времени эта схема не позволяет.
- **Общие тайминги.** `WORD_MORPH` — константа модуля и действует на все экземпляры на странице; для индивидуальных настроек нужно передавать опции в `initWordMorph` (сейчас не реализовано).
- **Скрытая вкладка оставляет слово в растворённом состоянии.** При скрытии таймеры останавливаются, класс `--morphing` (если он был включён) остаётся до возврата — на экране этого никто не видит, при возврате слово плавно проявляется. Учитывайте, если рядом с эффектом есть печать/скриншоты «в фоне».
- **Доступность.** Смена слова не объявляется скринридером (нет `aria-live`): при загрузке читается текущее слово, а дальше заголовок для него «тихо» меняется. «Призраки» скрыты от вспомогательных технологий (`aria-hidden` + `visibility: hidden`). Если смысл заголовка не должен зависеть от текущего слова, продублируйте его в `aria-label` или в визуально скрытом тексте.
- **Стоимость `filter: blur()`.** Размытие крупного текста перерисовывается на каждом кадре перехода. `will-change` не используется намеренно (постоянная композитная подложка ухудшает сглаживание текста); при слабых устройствах можно уменьшить `blurPx`.
- **`transition` между `none` и `blur()`.** В CSS специально указано `blur(0px)`, а не `none`, чтобы переход между чётким и растворённым состоянием интерполировался одинаково во всех браузерах.
- **Риски Safari (не проверялось):** анимация `filter` на тексте иногда перерисовывается рывками; при переносе проверьте Safari и при необходимости добавьте `-webkit-` префикс/`transform: translateZ(0)` на слово.
